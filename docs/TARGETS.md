# 功能集需求

- 提供 mihomo 内核所有 HTTP API 的支持，各个 API 在软件中以某种形式将功能提升给用户。
- 能够方便用户操作、让界面更好看的用户偏好都应该要能被持久化储存，除非对应的偏好
  需要的储存数据过大。

# 用户体验

- UI 必须针对小、中、大屏都做适配
- 不允许元素因为屏幕大小不够就超出界面
- 在小屏上，要减少在不可滚动位置放置尺码过大的元素，要让用户看到尽可能多的有用
  信息。这些元素会占据别的信息可能很需要的空间资源。
- 在单个界面上不要呈现过多的内容，要让用户能够一眼就看出界面上最重要的信息是什么。
  一个界面上重要的信息太多时，就应该考虑将该界面上的内容拆分成多个界面来放置。
- 在把一个界面的功能拆分成多个界面时，应该要让常用的内容、常用的信息在更外层的界面，
  使用频率低或者相对次要的信息，放到二级界面。
- 触屏设备与电脑的键鼠操作习惯不同，做适配时要考虑好不同设备上功能的使用方式是否
  合适。
- 单个界面内，不同的功能、信息应该要有明确的亲疏关系。相近、相似、相关的功能应该
  在空间上接近彼此，样式上也可以相似。

  如果相似的功能组块比较大，还可以考虑将其在视觉上明显地用块状表示出来——比如通过
  使用卡片样式。甚至直接把大的组块拆分到独立界面中。

# 样式

- 圆角
- 扁平化
- 整个项目的圆角要风格统一
- 颜色配置要考虑好是否随用户的主题切换而切换
- 样式也要尽量写成可以复用的形式
