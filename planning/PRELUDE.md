# 开发规划文档说明

项目根下的 CONTEXT.md 是项目的术语标准。

项目根下的 `planning` 目录用于存放项目的开发规划文档。面向用户与部署的资产
（示例配置、Compose 文件、界面截图等）存放在 `docs/`，不属于本目录范围。

其中的重要文件有：

- `PRELUDE.md`：即本文件，用于说明 `planning` 目录下各文件的信息
- `WORKFLOW.md`：开发流程惯例说明，此文件相对重要，在开始进行开发前都应该了解其内容
- `TARGETS.md`：用于记录推导本项目需求的基本准则，确定了当前项目中最重要的用户体验、
  和功能目标。在发现新问题、提出新需求时应该参考本文件。
  当本文件的准则与 `packages/ui/PRODUCT.md`、`packages/ui/DESIGN.md` 冲突时，以本
  文件为准。
- `DEV.md`：指向开发者信息的权威来源
- `TODO.md`：计划入口，以 Markdown TODO list 的形式记录各个开发目标。
  每个功能组块自带一个一级标题表明身份，各个开发目标则按自身特点下属于不同的功能
  组块。
- `feature/*.md`：按需创建，特性实施文档
- `report/*.md`：按需创建，功能或重构的设计与实现报告。重构前收录架构与实现方式的
  设计，实现并验收后收录结果与结论。
- `knowledge/*.md`：按需创建，为项目问题修正、新需求的提出、功能实现所作的调研，是从
  项目之外获取的知识。当认为获取到的信息能够帮助未来新功能的开发、旧功能的纠错时，
  就可以把该信息固化为此处的文档。
