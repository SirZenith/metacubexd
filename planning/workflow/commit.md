本文档描述本项目提交代码时应遵守的规约。

# 提交信息

- 使用英文 Conventional Commits（如 `feat: ...`、`fix: ...`、`docs: ...`、`refactor: ...`）。
- 简明描述本次需求；必要时用正文列出要点。

# 范围与安全

- 提交内容限于本次需求所必需的文件，不夹带无关改动。
- **绝不执行 `git push` 或任何远程写操作。**
- 不提交半成品；失败或受阻时保留工作区并说明状态（见 `blocked.md`）。

# 测试改动的单独提交

- 在「测试步骤」之外修改或删除测试时，把测试修改**单独作为一次提交**，并在提交信息中注明原因。

# 取短 hash

- 提交后用 `git log -1 --format=%h` 取短 hash，用于回写 TODO 条目的 `hash` 字段。
